日期：2026-07-22

## 当前执行目标

把真实用户反馈从“问题清单”推进到可验证产品能力。每一项升级必须能回答三个问题：

- 用户问什么。
- 产品怎么给判断。
- 用户能否打开来源继续核对。

自动评测命令：

```powershell
npm.cmd run audit:online-ai
```

输出文件：

- `analysis-output/online-ai-flow-audit-*.json`
- `analysis-output/real-user-ai-evaluation-*.md`

评测摘要会按用户角色、研究阶段、原始问题、系统识别、证据来源、失败恢复和用户判断记录结果。

## 真实用户测试记录模板

| 字段 | 记录内容 |
| --- | --- |
| 用户角色 | 家长 / 教练 / 剑馆管理者 / 赛事运营 / 数据用户 |
| 研究阶段 | 新用户探索 / 赛前准备 / 成长复盘 / 选馆对比 / 招生沟通 |
| 原始问题 | 用户真实输入，不改写 |
| 系统识别 | 赛事统计 / 赛前情报 / 选手成长 / 俱乐部对比 / 未收录恢复 |
| 首屏结论 | 是否一屏看懂 |
| 证据来源 | 是否能打开赛事、选手、俱乐部或项目 |
| 失败恢复 | 是否给出下一步 |
| 用户判断 | 可信 / 基本可用 / 需要补数据 / 不可用 |
| 产品动作 | 修文案 / 补路由 / 补数据 / 改详情页 / 改账号关注 |

## 本轮完成口径

本轮不追求一次性完成所有长期能力。完成口径是：

- 赛前情报在没有关注对象时，只展示赛事、报名和结构信息。
- 赛前情报在有关注对象时，才展示个人相关线索。
- 固定回归问题和真实用户测试记录有明确模板，后续每次反馈都能进入同一套执行板。
- 俱乐部项目分析有可点击证据；如果缺少匹配项目证据，回退到俱乐部画像，不给用户空来源。
