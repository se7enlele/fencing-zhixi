# FencingAI 真实用户反馈升级路线

日期：2026-07-23

## 目标

这份路线基于近期真实用户输入和模糊反馈整理。升级重点不是继续增加页面，而是把用户从“主动搜索数据”带到“提出问题后得到可核对判断”。

主链路统一为：

`提问 -> 识别意图 -> 给出判断 -> 展示证据 -> 深入核对 -> 关注/保存/提醒 -> 后续复用`

## 当前判断

产品已经具备赛事、选手、俱乐部、报名和赛果的基础数据能力，但真实用户暴露出三个核心问题：

1. 用户不会按系统结构提问，会直接问决策问题。
2. 用户需要先看到结论，再决定是否看证据。
3. 用户一旦发现证据跳错、文案像内部说明、未命中没有恢复动作，就会降低信任。

## P0：主链路升级

### 1. AI 意图识别分流

用户问题：

- `北京击剑联赛第一站`
- `2026年天津有几场比赛`
- `哪场比赛人数最多`
- `蔡廷彧最近有没有进步`
- `北京金石和北京艾鲁特U10男花谁更强`

升级内容：

- 赛事名称查询：识别赛事名，不误跳到相似旧赛事。
- 赛事统计：识别年份、城市、月份、状态。
- 赛事排行：识别“最多、最大、人数最多”等规模意图。
- 选手成长：识别姓名、年份变化、近期变化。
- 俱乐部对比：识别两家俱乐部、年份、年龄段、剑种、性别。
- 赛前情报：识别报名中、未开赛和已结束的区别。
- 人员查询：支持教练员、裁判员目录类问题。

验收标准：

- 问题类型识别正确。
- 没有明确对象时给出补充条件，而不是直接给空结果。
- 统计问题不进入普通搜索结果。

### 2. AI 回答首屏结构

用户问题：

- 结果信息太散。
- 出现“分析口径、判断路径、后续、数据边界”等不适合商业产品的文案。
- 用户需要先看结论，而不是先看系统如何分析。

升级内容：

- 首屏固定为：一句话结论、关键理由、核心数字、可核对记录、下一步动作。
- 对比类结果必须区分成绩积累、效率信号和样本规模。
- 证据区域只展示用户能理解的“可核对记录”，不展示内部匹配过程。
- 加载过程需要有状态、骨架屏和自动定位。

验收标准：

- 首屏一屏能看懂结论。
- 页面不出现内部流程型文案。
- 每个强判断至少有一个可打开来源。

### 3. 证据链闭环

用户问题：

- 用户会核对 AI 结论。
- 证据跳错比没有证据更伤信任。

升级内容：

- 赛事统计结果能打开筛选后的赛事列表。
- 赛事名称结果能打开赛事详情。
- 选手成长结果能打开选手画像和参赛记录。
- 俱乐部对比结果能打开两家俱乐部和相关赛事。
- 项目类证据优先打开稳定详情；详情缺数据时回退到赛事或俱乐部画像。

验收标准：

- 来源页面与问题条件一致。
- AI 到数据库的筛选条件保留。
- 用户不需要重新输入同一组条件。

### 4. 未命中和模糊问题恢复

用户问题：

- `孩子击剑值不值得继续`
- `为什么没有北京击剑联赛的数据`
- `天津比赛`
- `小众`

升级内容：

- 未识别对象时，提示选择选手、赛事或俱乐部。
- 未收录赛事时，区分“未收录、未导入项目、暂无报名、暂无成绩”。
- 模糊俱乐部或选手搜索，优先给可选对象。
- 家长类模糊问题先引导选择孩子，不直接做价值判断。

验收标准：

- 失败页仍有明确下一步。
- 不把“未收录”表达成“没有这场比赛”。
- 不把报名数据伪装成赛果数据。

## P1：角色价值升级

### 5. 家长成长报告

用户关心：

- 孩子是否进步。
- 是否稳定。
- 是否值得继续投入时间和金钱。

升级内容：

- 固定结构：近期表现、年度变化、小组稳定性、淘汰赛表现、最好名次、最近名次、下一步观察。
- 文案使用“成长基础期、稳定积累期、突破观察期”等建设性表达。
- 不直接输出“谨慎投入”等刺激性判断。

验收标准：

- 家长一屏能知道孩子当前阶段。
- 所有判断都能回到参赛记录。

### 6. 赛前情报包

用户关心：

- 报名中或未开赛时，可能有哪些强手。
- 自己孩子或学员可能面对什么级别对手。

升级内容：

- 未选择孩子/学员时，只展示报名热度、重点俱乐部、历史强手。
- 选择孩子/学员后，再展示熟悉对手、潜在强手、历史交手和备赛重点。
- 根据赛事状态区分报名中、未开赛、比赛中、已结束。

验收标准：

- 不虚构真实对阵。
- 能解释当前数据来自报名名单还是历史成绩。

### 7. 教练工作台

用户关心：

- 带好现有学员。
- 留住家长。
- 招到新学员。
- 维护俱乐部口碑。

升级内容：

- 俱乐部页从结果展示升级为学员分层。
- 默认展示重点跟进学员、优势项目、薄弱项目、近期赛事。
- 支持按剑种、年龄段、性别查看。
- 增加可复制的家长沟通摘要。

验收标准：

- 教练视角不出现“我的孩子”。
- 教练能快速知道关注谁、练什么、怎么沟通。

### 8. 剑馆招生名片

用户关心：

- 如何把成绩变成对外可信表达。

升级内容：

- 生成剑馆名片：代表选手、优势项目、前八、奖牌、最好名次、活跃赛事。
- 文案面向潜在家长，不出现内部分析术语。
- 支持复制摘要或保存卡片。

验收标准：

- 小型剑馆也能形成可信展示。
- 所有数字可追溯，不夸大排名。

## P2：持续服务能力

### 9. 数据库作为证据层

升级内容：

- 数据库页定位为核对、检索、筛选和详情入口。
- 首页负责提问和判断，数据库页不重复首页。
- 支持赛事、选手、俱乐部、教练员、裁判员搜索。
- 筛选项按年份、地区、项目、状态和关注范围排序。

验收标准：

- 从 AI 跳转到数据库后保留筛选。
- 数据库页不出现内部数据处理文案。

### 10. 关注、保存和提醒

升级内容：

- 关注对象覆盖选手、赛事、俱乐部、报告。
- 已关注状态使用小 tag 或 icon。
- 首页优先展示关注对象变化、重点赛事和最近报告。

验收标准：

- 关注状态清晰但不突兀。
- 用户能快速回到最近关心的对象。

### 11. 登录和账号体系

升级内容：

- 明确未登录和已登录状态。
- 未登录：可浏览公开数据，本地保存关注。
- 已登录：同步关注、历史、报告和提醒。
- 登录表单放在独立页面，不在“我的”页直接展开。
- 第一阶段使用手机号/邮箱加密码，后续再接微信登录。

验收标准：

- 已登录时不显示登录表单。
- 未登录时不显示账号级身份语义。

### 12. 数据同步和覆盖状态

升级内容：

- 固定同步赛事列表、项目列表、报名名单、成绩数据、人员目录。
- 对每场赛事标记覆盖层级：赛事、项目、报名、成绩。
- 进行中赛事展示当前可用数据，不当作错误。

验收标准：

- 用户知道缺的是哪一层数据。
- 数据增加后不需要手工调整前端结构。

## 固定回归问题

每次上线前至少跑这些问题：

1. `北京击剑联赛第一站`
2. `2026年天津有几场比赛`
3. `哪场比赛人数最多`
4. `天津近期报名情况`
5. `蔡廷彧最近有没有进步`
6. `蔡廷彧2025和2026年的表现有什么变化`
7. `北京金石和北京艾鲁特U10男花谁更强`
8. `看2025和2026年，花剑，男子和女子，北京金石是不是比北京艾鲁特更好`
9. `山东小众体育U8男花怎么样`
10. `山东小众体育招生怎么讲`
11. `分析马潇和陶嘉月的对战情况`
12. `帮我生成蔡廷彧成长报告`
13. `帮我生成赛前情报包`
14. `孩子击剑值不值得继续`
15. `为什么我的数据库里没有北京击剑联赛的数据`
16. `能搜索教练员和裁判员么`

## 建议执行顺序

第一轮：

1. AI 意图识别。
2. AI 回答结构。
3. 证据链跳转。
4. 模糊和未命中恢复。

第二轮：

1. 家长成长报告。
2. 赛前情报包。
3. 教练工作台。
4. 剑馆招生名片。

第三轮：

1. 数据库证据层。
2. 关注、保存、提醒。
3. 登录和账号体系。
4. 数据同步和覆盖状态。
