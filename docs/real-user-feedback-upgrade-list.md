# FencingAI 真实用户反馈后续升级清单

## 结论

这轮反馈暴露的核心问题不是页面数量不够，而是产品还没有完全形成“提问 -> 判断 -> 证据 -> 继续动作 -> 保存复用”的闭环。后续升级应优先围绕 AI 主入口、证据链、失败恢复和角色化决策场景推进。

## P0：必须优先处理

### 1. AI 意图识别路由

用户会直接输入赛事名、选手名、俱乐部名、统计问题、成长问题、对比问题和赛前问题。当前最大风险是系统把这些问题混在一起处理，导致命中对象错误或无法回答。

待升级内容：

- 区分赛事名称查询、赛事数量统计、赛事规模排行。
- 区分选手成长、选手对比、俱乐部对比。
- 区分赛前报名情报、历史成绩分析和真实对阵分析。
- 对模糊问题先追问关键条件，而不是直接空结果。

验收问题：

- `北京击剑联赛第一站`
- `2026年天津有几场比赛`
- `哪场比赛人数最多`
- `蔡廷彧最近有没有进步`
- `北京金石和北京艾鲁特U10男花谁更强`

### 2. 首页 AI 答案结构

用户不需要看到系统如何分析，需要先看到结论、关键数字和可打开的来源。当前页面容易把“分析口径、判断路径、后续、数据边界”等实现视角文案暴露出来。

待升级内容：

- 首屏固定为一句话判断、2 到 4 个关键数字、关键证据、下一步动作。
- 移除所有内部工作流文案。
- 对比类问题必须区分“数量优势”和“质量优势”，不能把参赛次数多直接说成训练更好。
- 提交问题后立即滚动到结果区域，并显示 loading 或骨架屏。

验收标准：

- 一屏内能看懂结论。
- 页面不出现内部术语。
- 用户知道下一步可以打开证据、继续筛选、关注或生成报告。

### 3. 证据链闭环

真实用户会核对 AI 结论。一旦结论不能跳回赛事、项目、选手或俱乐部来源，信任会下降。

待升级内容：

- AI 结果中的证据必须可点击打开。
- 俱乐部对比要能打开两家俱乐部。
- 选手成长要能打开参赛记录。
- 赛事统计要能打开对应赛事列表或详情。
- 报告类结果要保留证据样本。

### 4. 失败恢复

未命中不是结束状态，而应该引导用户补充条件或进入相关数据。

待升级内容：

- 未识别时提示用户补充赛事名、选手名、俱乐部、年份、地区、年龄段、剑种、性别、状态。
- 未收录赛事时明确说“当前未收录这场赛事”，不要误导到其他年份或近似赛事。
- 对“孩子击剑值不值得继续”这类问题，先引导选择或关注一个孩子。

## P1：提升复用和信任

### 5. 家长成长报告

家长关心的不是数据本身，而是孩子是否进步、是否稳定、是否值得继续投入。

待升级内容：

- 固定展示近期表现、年度变化、小组稳定性、淘汰赛表现、最好名次、最近名次。
- 用“成长基础期、稳定积累期、突破观察期”等表达替代“谨慎投入”等刺激性文案。
- 所有判断都能回到具体参赛记录。

### 6. 赛前情报包

报名数据和历史成绩数据需要分层呈现，不能把报名名单直接推断为真实对阵。

待升级内容：

- 展示赛事和项目概览。
- 展示报名名单中的重点选手。
- 结合“我的孩子”或“我的学员”识别强手和熟悉对手。
- 没有选定关注对象时，不直接说“可能对手”。

### 7. 教练工作台

教练关注的是学员管理、训练重点、留住家长和剑馆口碑，不应该看到家长视角的“我的孩子”。

待升级内容：

- 默认展示学员分层、重点跟进学员、强项项目、弱项项目。
- 给出可复制的家长沟通话术。
- 结合近期赛事提醒教练哪些项目值得重点备赛。

### 8. 剑馆招生展示

剑馆管理者需要把数据变成对外可信的成绩资产。

待升级内容：

- 生成剑馆名片：代表成绩、代表选手、优势项目、赛事活跃度。
- 文案面向家长表达，不出现内部分析术语。
- 支持保存或复制摘要，用于招生沟通。

### 9. 数据库页重定位

数据库页不应和首页 AI 抢入口，它应该作为证据层和深度检索层。

待升级内容：

- 从 AI 问答进入数据库时保留筛选条件。
- 数据库页顶部说明当前筛选条件来自哪次问题。
- 筛选项按年份、地区、项目、状态排序。
- 支持搜索选手、俱乐部、教练员、裁判员。

## P2：商业化和长期使用

### 10. 关注、保存、提醒

用户长期使用的前提是能持续追踪自己关心的对象。

待升级内容：

- 关注对象覆盖选手、赛事、俱乐部、报告。
- 已关注状态用小 tag 或 icon 呈现。
- 首页围绕关注对象展示孩子、赛事提醒、最近报告。

### 11. 登录和账户体系

登录的价值是同步关注、报告、历史和提醒，不应该和未登录状态混在同一套表达里。

待升级内容：

- 明确已登录和未登录两种状态。
- 未登录允许浏览公开数据和本地保存关注。
- 已登录同步关注、历史、报告和提醒。
- 第一阶段可用手机号加密码，第二阶段再接入微信登录。

### 12. 报告产品化

报告是从数据查询走向商业化服务的关键形态。

优先报告类型：

- 家长成长报告。
- 赛前情报包。
- 教练学员分层报告。
- 剑馆招生名片。

验收标准：

- 每类报告有固定结构。
- 能从 AI 问答自然生成。
- 可以保存、复制摘要、再次打开。

### 13. 数据同步和覆盖提示

数据持续增长后，用户需要知道“没有结果”到底是没有比赛、没有导入，还是还没形成成绩。

待升级内容：

- 区分赛事列表、项目名单、报名名单、成绩数据四种覆盖状态。
- 对未收录赛事给出清晰状态和下一步。
- 正在比赛、报名中、未开赛、已结束等状态要在前台有对应表达和筛选。

## 推荐实施顺序

### 第一轮：AI 主链路

1. AI 意图识别路由。
2. 首屏答案结构压缩。
3. 失败恢复。
4. 证据链跳转闭环。

### 第二轮：核心用户场景

1. 家长成长报告。
2. 赛前情报包。
3. 教练工作台。
4. 剑馆招生展示。

### 第三轮：持续服务

1. 关注和提醒。
2. 登录状态重构。
3. 报告保存和复用。
4. 数据覆盖状态提示。

## 发布前固定回归问题

每次发布前至少跑这些问题：

1. `北京击剑联赛第一站`
2. `2026年天津有几场比赛`
3. `哪场比赛人数最多`
4. `蔡廷彧最近有没有进步`
5. `蔡廷彧2025和2026年的表现有什么变化`
6. `天津近期报名情况`
7. `山东小众体育U8男花怎么样`
8. `山东小众体育招生怎么讲`
9. `北京金石和北京艾鲁特U10男花谁更强`
10. `分析马潇和陶嘉月的对战情况`
11. `帮我生成蔡廷彧成长报告`
12. `帮我生成赛前情报包`
13. `孩子击剑值不值得继续`
